# 사내톡 유스케이스

## 문서 범위

이 문서는 현재 저장소의 구현 기능과 요구사항분석서 v2를 바탕으로 사용자 관점의 유스케이스를 정리한다. 역할과 흐름은 제품 범위를 설명하며, 각 기능의 실제 담당 개발자는 별도 프로젝트 기록에서 확인한다.

## 액터

| 액터 | 설명 |
| --- | --- |
| 일반 사용자 | 사내 계정으로 로그인해 동료와 대화하고 파일을 주고받는 직원 |
| 관리자 | 가입·계정 상태·감사 기록 등을 관리하는 권한 사용자 |
| 서버 운영자 | 서버 설정, DB, TLS, 백업, Windows 서비스와 배포를 관리하는 담당자 |

## 상세 흐름

### UC-01 가입 신청 및 승인

- **목표:** 직원이 사내톡 계정을 만든다.
- **시작 조건:** 클라이언트가 서버에 연결되어 있고, 가입이 허용된 상태다.
- **기본 흐름:**
  1. 사용자가 회원가입 화면을 연다.
  2. 사원번호, 이메일, 이름, 부서, 직급, 비밀번호 등 필요한 정보를 입력한다.
  3. 클라이언트가 입력 형식을 확인해 가입 요청을 보낸다.
  4. 서버가 이메일 도메인, 중복 계정, 비밀번호 정책을 확인하고 계정을 만든다.
  5. 자동 승인 설정이면 사용 가능 상태를 반환하고, 관리자 승인이 필요하면 승인 대기 상태를 반환한다.
  6. 사용자는 결과 안내를 확인한다.
- **대안·오류 흐름:** 형식 오류, 허용되지 않은 이메일 도메인, 중복 사원번호·이메일, DB 오류가 있으면 가입을 완료하지 않고 안내한다.
- **완료 상태:** 계정은 설정에 따라 활성화되거나 승인 대기 상태다.

### UC-02 TLS 로그인 및 자동 로그인

- **목표:** 계정 소유자가 안전하게 서버에 접속한다.
- **시작 조건:** 서버 주소와 포트가 설정되어 있다.
- **기본 흐름:**
  1. 클라이언트가 TCP 연결을 시작하고 TLS를 협상한다.
  2. 처음 보는 서버 인증서라면 사용자가 지문을 확인하고 신뢰 여부를 선택한다.
  3. 사용자가 사원번호와 비밀번호를 입력하거나, 허용된 저장 토큰으로 자동 로그인을 선택한다.
  4. 서버가 인증 상태·계정 상태·로그인 제한을 확인한다.
  5. 성공하면 사용자 정보와 동료·방 목록을 받고 메인 화면으로 이동한다.
- **대안·오류 흐름:** 인증서 지문이 저장된 값과 다르거나, 계정이 승인 대기·정지 상태이거나, 로그인 실패 제한에 걸리면 접속을 거부하고 이유를 안내한다.
- **완료 상태:** 사용자 세션이 연결되어 메시지를 주고받을 수 있다.

### UC-03 동료 찾기, 친구·프로필·상태 관리

- **목표:** 대화할 직원을 찾고 서로의 기본 정보를 확인한다.
- **기본 흐름:**
  1. 사용자가 동료 목록 또는 사람 찾기를 연다.
  2. 사원번호나 지원되는 검색 정보로 대상을 찾는다.
  3. 프로필 카드에서 표시 정보와 상태를 확인하고 친구 추가·삭제를 선택한다.
  4. 자신의 상태와 상태 메시지, 프로필 사진을 변경한다.
- **대안·오류 흐름:** 대상을 찾지 못하거나 서버 요청이 실패하면 목록을 유지하고 오류를 안내한다.
- **완료 상태:** 친구 목록·프로필·상태가 서버에 반영된다.

### UC-04 1:1 메시지 주고받기

- **목표:** 두 직원이 개인 대화를 나눈다.
- **기본 흐름:**
  1. 사용자가 동료를 선택해 1:1 대화창을 연다.
  2. 메시지를 입력해 전송한다.
  3. 서버가 발신자를 세션 정보로 확인하고 대화 기록을 저장한다.
  4. 상대가 접속 중이면 즉시 전달하고, 오프라인이면 기록을 보관한다.
  5. 상대가 나중에 로그인하면 안 읽은 대화 알림과 기록을 확인한다.
- **대안·오류 흐름:** 권한 없는 대상, 길이 제한 초과, 연결·DB 오류가 있으면 서버가 요청을 거부하거나 오류를 반환한다.
- **완료 상태:** 메시지는 해당 대화 참여자에게만 표시되고 기록에 남는다.

### UC-05 채팅방 생성·초대·대화

- **목표:** 여러 직원이 한 공간에서 대화한다.
- **기본 흐름:**
  1. 사용자가 방 이름, 정원, 공개 여부를 정해 방을 만든다.
  2. 필요한 경우 직원을 초대한다.
  3. 참여자가 방에 입장해 메시지, 답장, 공감 등 대화 기능을 사용한다.
  4. 서버가 방 멤버와 권한을 확인한 뒤 메시지를 전달하고 기록을 저장한다.
- **대안·오류 흐름:** 비공개 방 초대 없이 입장하거나 정원이 찬 방에 입장하려 하면 거부한다. 방장 권한이 필요한 작업은 권한을 확인한다.
- **완료 상태:** 방과 멤버 정보, 대화 기록이 저장된다.

### UC-06 파일 전송

- **목표:** 1:1 대화 또는 채팅방에서 파일을 공유한다.
- **기본 흐름:**
  1. 사용자가 파일을 선택해 전송을 시작한다.
  2. 서버가 파일 크기·이름·대화 참여 권한을 확인한다.
  3. 파일은 여러 조각으로 전송되고, 진행 상태가 화면에 표시된다.
  4. 받는 사용자는 파일을 내려받고, 완료된 파일은 대화 기록에서 확인한다.
- **대안·오류 흐름:** 파일 크기 제한, 권한, 네트워크 또는 저장 오류가 발생하면 실패를 알리고 임시 전송 상태를 정리한다. 사용자가 취소할 수 있다.
- **완료 상태:** 파일 메타데이터와 저장 위치가 기록되고 권한이 있는 사용자만 받을 수 있다.

### UC-07 대화 기록 조회·검색·읽음 처리

- **목표:** 이전 대화를 이어 보고 필요한 메시지를 찾는다.
- **기본 흐름:**
  1. 사용자가 방 또는 1:1 대화창을 연다.
  2. 서버가 사용자가 볼 수 있는 최근 기록을 반환한다.
  3. 사용자는 이전 기록을 더 불러오거나 검색한다.
  4. 메시지를 읽으면 읽음 위치가 갱신되고, 지원되는 대화에서는 읽음 상태가 표시된다.
- **대안·오류 흐름:** 권한이 없는 방이나 검색 범위의 메시지는 반환하지 않는다. DB 오류나 요청 제한 초과 시 안내한다.
- **완료 상태:** 허용된 범위의 대화가 표시되고 읽음 위치가 저장된다.

### UC-08 가입·계정 관리와 감사 기록 확인

- **목표:** 관리자가 계정 접근을 통제하고 운영 작업을 추적한다.
- **기본 흐름:**
  1. 관리자가 관리자 화면 또는 서버 콘솔에서 가입 대기자·계정을 조회한다.
  2. 가입 승인·거절, 계정 정지·복구, 비밀번호 초기화, 강제 로그아웃 등의 작업을 선택한다.
  3. 서버가 관리자 권한과 대상 계정 상태를 확인한다.
  4. 작업 결과를 반영하고 감사 기록에 남긴다.
  5. 관리자가 감사 로그와 통계를 조회한다.
- **대안·오류 흐름:** 권한이 없거나 자기 자신·마지막 관리자를 보호하는 규칙을 위반하면 작업을 거절하고 기록한다.
- **완료 상태:** 계정 상태가 갱신되며 처리 결과가 감사 로그에 남는다.

### UC-09 서버와 서비스 운영

- **목표:** 서버 운영자가 메신저 서버를 시작하고 정상 상태로 유지한다.
- **기본 흐름:**
  1. 운영자가 서버 설정, DB 연결, TLS 인증서, 파일 저장 위치를 준비한다.
  2. 서버가 스키마 버전과 필요한 설정을 확인하고 포트에서 접속을 기다린다.
  3. Windows 서비스 실행 시 감독 프로그램이 서버 프로세스를 시작하고 종료 상태를 감시한다.
  4. 정상 종료 때 세션과 기록 저장을 정리하고, 비정상 종료 시 설정된 간격으로 재시작을 시도한다.
- **대안·오류 흐름:** 설정·DB·포트·인증서 오류가 있으면 로그를 남기고 운영자가 확인할 수 있게 안내한다.
- **완료 상태:** 서버가 준비 상태로 실행되거나, 실패 원인이 운영 로그에 기록된다.
