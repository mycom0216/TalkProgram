## 2-1. 채팅방·메시지 기능 시나리오 테스트 (실제 MariaDB, 40개)

진짜 서버에 TLS로 붙은 가상 사용자 3명이 차례로 동작하고 결과를 확인한다. 2026-10-28 실행: **40개 통과, 0개 실패**.

- 옛 버전(v0) 클라이언트 로그인 거절
- 비공개 방 만들기 + 만들면서 초대 → 초대받은 사람에게 바로 도착, 다른 사람 목록에는 안 보임, 초대 없이 입장 거절
- 메시지 번호, 답장(원문 요약), **다른 방 메시지는 인용 불가**
- 공감 반영, 허용되지 않은 이모지 무시, 읽음 알림
- 삭제 권한(남의 방·남의 메시지 거절), 삭제 알림
- 검색: 방 이름 포함, 2초 간격 제한, 삭제된 메시지 제외, **비멤버는 비공개 방 메시지를 못 찾음**
- 접속하지 않은 사람에게 1:1(500자 자르기), 로그인 때 "안 읽은 1:1" 요약, 1:1 지난 대화
- 회사 사람 목록, 공개 방 초대 → RoomUpdate(멤버 수), **접속하지 않은 사람에게 1:1 파일 → 다시 접속하면 지난 대화에 있음**
- **서버 재시작 후**: 방·멤버 유지, 삭제 표시·공감·답장 인용(원문 삭제됨) 유지, 읽음 위치 유지
- 마지막 멤버가 나가면 방이 닫힘
- 방 삭제: 방장이 아니면 거절, 방장이 삭제하면 접속한 멤버 모두에게 알림, 목록에서 사라짐
- 방장 넘기기: 방장이 아니면 거절, 넘기면 새 방장 반영·알림, 방장이 그냥 나가면 가장 먼저 들어온 멤버가 자동으로 방장

## 3. 보안 검증 (TLS)

| 확인 | 방법 | 결과 |
| --- | --- | --- |
| 대화·비밀번호가 암호화되는지 | 클라이언트와 서버 사이에 중계 프로그램을 두고 오가는 바이트를 전부 저장한 뒤 검색 | **평문 모드**: 비밀번호·메시지가 그대로 보임 / **TLS 모드**: 0회 |

| 저장한 지문과 다름 (중간자 공격 흉내) | 다른 지문으로 접속 | 연결 거부 (`Changed = true`) |
| 평문 클라이언트 → TLS 서버 | 평문 패킷 전송 | 서버가 즉시 끊음 |
| TLS 클라이언트 → 평문 서버 | TLS 인사말 전송 | 서버가 알아보고 0.1초 안에 끊음 (고치기 전에는 10초 대기) |
| 아무것도 보내지 않는 연결 | 접속만 하고 대기 | 10초 뒤 서버가 끊음 (핸드셰이크 시간 제한) |

## 4. 부하 테스트

모든 가상 사용자가 같은 방("전체 채팅")에서 일정 간격으로 메시지를 보내고, 전원이 모든 메시지를 받는지 확인했다.

| 사용자 | 서버가 전달한 패킷 | 유실 | 순서 어긋남 | 지연 중앙값 / 99% | 서버 메모리 |
| --- | --- | --- | --- | --- | --- |
| 100명 | 5,000개/초 | 0 | 0 | 4ms / 15ms | 124MB |
| 300명 | 42,177개/초 | 0 | 0 | 129ms / 515ms | 178MB |
| 300명 (TLS) | 43,202개/초 | 0 | 0 | 178ms / 567ms | 232MB |
| 500명 | 46,771개/초 | 0 | 0 | 276ms / 867ms | 287MB |

부하 테스트로 찾아 고친 병목은 두 가지다. 300명 기준으로 지연 중앙값이 458ms에서 129ms로, 메모리가 718MB에서 178MB로 줄었다.

1. 같은 메시지를 받는 사람마다 JSON으로 다시 변환하던 것을 한 번만 변환하도록 바꿨다.
2. 접속자 목록을 로그인할 때마다 즉시 방송하던 것(N³)을 200ms마다 묶어서 한 번만 보내도록 바꿨다.

관리자 기능을 넣은 뒤 다시 돌린 100명 TLS 테스트에서도 유실 0, 지연 중앙값 5.8ms로 성능이 떨어지지 않았다.

## 5. 화면 점검표 (WinForms, 사람이 직접 확인)

화면 동작은 자동 테스트가 어려워서 점검표로 확인한다. 큰 기능을 바꾼 뒤에는 다시 한 번 훑어본다.

**로그인·보안**
- [ ] 처음 접속할 때 인증서 지문 확인 창이 뜨고, 서버 콘솔 `/tls`의 지문과 같다
- [ ] 두 번째 접속부터는 확인 창 없이 연결되고 상태 표시줄에 "암호화 연결됨"이 보인다
- [ ] 로그인 5회 실패 후 잠김 안내가 나온다
- [ ] 임시 비밀번호로 로그인하면 비밀번호 변경 창이 먼저 뜨고, "로그아웃"을 누르면 로그인 화면으로 돌아간다

**채팅**
- [ ] 전체 채팅, 1:1 대화, 채팅방(만들기·입장·나가기)이 된다
- [ ] 방에 들어가면 지난 대화 50개와 "여기까지 지난 대화" 구분선이 보인다
- [ ] @이름 멘션이 강조되고 알림 창이 뜬다. 방해 금지 상태에서는 뜨지 않는다
- [ ] Ctrl+F 검색으로 이전/다음 결과로 이동한다
- [ ] 말풍선 오른쪽 클릭 → 답장/공감/복사/삭제. 더블클릭하면 답장. 답장 막대의 ✕(또는 Esc)로 취소
- [ ] 답장 말풍선 위 인용을 누르면 원래 메시지로 이동하고 강조된다
- [ ] 공감 칩(👍 2)을 누르면 내 공감이 켜지고/꺼지며, 내가 누른 칩은 파란 테두리
- [ ] 삭제하면 모두의 화면에서 "삭제된 메시지입니다."로 바뀌고, 그 메시지를 인용한 답장도 바뀐다
- [ ] 방(기본 방 제외)과 1:1에서 안 읽은 사람 수가 시각 위에 보이고, 상대가 창을 보면 줄어든다
- [ ] 비공개 방을 만들면 초대할 사람 고르기 창이 뜨고, 방 창의 [초대]로 더 부를 수 있다
- [ ] 방 창 머리에 "멤버 N명 · 접속 M명"이 보인다
- [ ] 내 이름 메뉴 → 전체 대화 검색: 결과를 더블클릭하면 그 대화가 열리고 메시지로 이동한다
- [ ] 내 이름 메뉴 → 동료 찾기: 접속하지 않은 사람에게도 1:1을 보낼 수 있고, 다음 로그인 때 그 사람에게 알림이 뜬다

**파일**
- [ ] [+] 메뉴에서 사진·동영상·파일을 따로 고를 수 있고, 끌어다 놓기와 Ctrl+V도 된다
- [ ] 사진은 미리보기가 보이고, 큰 파일은 진행률이 보인다. 전송 중에도 채팅이 된다
- [ ] 보내는 중·받는 중에 취소할 수 있다
- [ ] 실행 파일(.exe 등)을 열 때 경고가 뜬다

**연결**
- [ ] 서버를 껐다 켜면 2→4→8초 간격으로 다시 연결하고, 참여하던 방이 복구된다
- [ ] 같은 계정으로 다른 곳에서 로그인하면 이전 창에 안내가 뜨고 다시 연결하지 않는다
- [ ] X를 누르면 트레이로 숨고, 트레이 메뉴 "종료"로만 끝난다
- [ ] 내 이름 메뉴(또는 트레이) → 로그아웃 → 로그인 화면으로 돌아오고 다른 계정으로 로그인된다
- [ ] 서버 설정에서 TLS를 끄고 원격 서버에 로그인하면 경고가 뜬다
- [ ] 서버 `ClientLatestVersion`을 더 높게 하면 "새 버전" 안내가 뜬다

**관리자**
- [ ] 관리자만 내 이름 메뉴에 "관리자 메뉴..."가 보인다
- [ ] 선택한 회원 상태에 맞는 버튼만 켜진다 (예: 승인은 승인 대기일 때만)
- [ ] 정지하면 그 사람 화면에 사유와 함께 끊김 안내가 뜬다
- [ ] 비밀번호 초기화 결과가 클립보드에 복사된다
- [ ] 감사 로그 탭에서 사원번호·동작으로 걸러 볼 수 있고, 로그인 실패는 빨간색이다
- [ ] 창을 줄여도 마지막 칸(마지막 로그인)까지 가로 스크롤 없이 보인다

## 알려진 한계

- 화면(WinForms)은 자동 테스트가 없다. 위 점검표로 확인한다.
- DB가 필요한 흐름(로그인 성공 이후)은 자동 테스트(CI)에 넣지 않았다. 실제 MariaDB로 시나리오 테스트를 했다.
- 시각은 서버 PC의 지역 시각을 쓴다. 서버와 다른 시간대에 있는 PC는 읽음 숫자·지난 대화 순서가 시간대 차이만큼 어긋날 수 있다(해외 지사가 생기면 UTC로 바꿀 것).
- 회사 사람 목록(초대·동료 찾기)은 서버가 30초 동안 기억해 두므로, 막 가입한 사람은 최대 30초 늦게 보인다.
- 부하 테스트는 서버와 테스트 도구가 한 대(2코어)에서 같이 돌아서, 지연 값에 테스트 도구의 부하도 섞여 있다. 실제 서버에서는 더 좋게 나올 것이다.
